# Контекст проекта UNIVERSE DESIGN

## Что это за проект
- Статический сайт-портфолио студии `UNIVERSE DESIGN`.
- Технологии: чистые `HTML/CSS/JavaScript` (без фреймворков).
- Хостинг: GitHub Pages, домен задается через `CNAME`.

## Ключевая структура
- Главная: `index.html` + `script.js` (интерактивный куб, меню, overlay).
- Список проектов: `projects.html`.
- Страница о студии: `about.html`.
- Общие стили: `style.css`.
- Стили страниц проектов: `projects/projects.css`.
- Каждая страница проекта: `projects/<slug>.html`.
- Медиа проекта: `projects/<slug>/covers/cover.jpg` и `projects/<slug>/gallery/*`.
- Логика полноэкранной галереи проектов: `projects/project-gallery.js`.
- Обнаружение поисковиками и AI-агентами: `robots.txt` и `sitemap.xml` в корне.
- Текстовый слой для LLM-агентов: `llms.txt` в корне + `.md`-зеркало каждой страницы
  по тому же пути (`about.html` → `about.md`, `projects/echo_2.0.html` → `projects/echo_2.0.md`).
- `.nojekyll` в корне обязателен: без него GitHub Pages прогоняет `.md` через Jekyll.

## Как обычно добавлять новый проект
1. Создать папку `projects/<slug>/` с:
   - `covers/cover.jpg`
   - `gallery/` с файлами `image*.jpg/png` и `gif*.gif` (без пробелов/кириллицы в именах).
2. Создать страницу `projects/<slug>.html` по шаблону существующих проектов.
   Обязательный минимум в `<head>`: `<link rel="canonical">`, `<meta name="description">`,
   блок Open Graph/Twitter, JSON-LD. Скопировать целиком с соседней страницы проекта
   и заменить URL, описание и `og:image` на обложку нового проекта.
3. Добавить карточку проекта в `projects.html`:
   - блок в сетке карточек;
   - запись в JSON-LD (`itemListElement`).
4. **Дописать URL страницы в `sitemap.xml`.** Сборки нет, файл статический — сам он не обновится.
   Если в имени файла есть кириллица, URL percent-энкодить (пример: `UNIVERSE%D1%85LedPulse.html`).
5. **Создать `projects/<slug>.md`** по образцу соседнего проекта (описание, ссылки на видео,
   обложку и файлы галереи), добавить `<link rel="alternate" type="text/markdown">` в `<head>`
   HTML-страницы и запись о проекте в `llms.txt` и `projects.md`.
6. Проверить мобильную и десктопную верстку (особенно GIF и iframe-видео).

## Важные практики для правок
- `.DS_Store` закрыт в `.gitignore` — руками ничего делать не нужно.
- Перед коммитом проверять `git status` и состав staged-файлов.
- Если есть файл `README.md` локально, проверять необходимость его добавления в релиз отдельно.
- Для Vimeo/YouTube учитывать, что базовые контейнеры в `projects/projects.css` ориентированы на `16:9`; портретные видео требуют отдельного класса/медиа-правила.

## Чего на этом хостинге сделать нельзя
GitHub Pages отдаёт статику и не позволяет задавать свои HTTP-заголовки
и делать content negotiation. Поэтому недоступны:
- `Link`-заголовки (RFC 8288) — нужен прокси вроде Cloudflare;
- Markdown negotiation по `Accept: text/markdown` — то же самое.

Домен сейчас смотрит прямо на GitHub Pages (NS у reg.ru, A-записи `185.199.108–111.153`).
Cloudflare как решение отвергнут: плохо работает в России.

## Альтернативная версия сайта: `canvas/` (только в ветке `feature/canvas`)

Отдельный проект на Vite + React + R3F. **Не пересекается с боевым сайтом:**
GitHub Pages деплоит `main`, а `canvas/` живёт в своей ветке и выкладывается
на собственный VPS.

- Превью: `http://169.58.96.104/` (позже — `https://canvas.universe-design.com`),
  закрыто заголовком `X-Robots-Tag: noindex`.
- Конфиг nginx — `canvas/deploy/nginx.conf`, копия на сервере в
  `/etc/nginx/sites-available/canvas`. Правится **в репозитории**, потом копируется:
  сервер должен пересоздаваться из кода.
- Деплой — `.github/workflows/canvas-deploy.yml`, срабатывает на пуш в
  `feature/canvas`. Ходит на сервер под пользователем `deploy`, не под root.
- SSH к серверу — по алиасу `vps` из `~/.ssh/config`; прямой `root@IP` не пускает.

### Правила, которые легко нарушить

- **Пути к медиа — только через `canvas/src/lib/media.js`.** Ни один компонент не пишет
  путь напрямую. Решение по хостингу за месяц менялось дважды, и следующий переезд
  должен быть правкой одного файла.
- **`MEDIA_BASE` в `media.js` и `location /media/` в `nginx.conf` — одна и та же
  величина в двух местах.** Менять только вместе.
- **Видео не хранится в гите.** Лежит на сервере в `/var/www/canvas-media/`, туда же
  постеры. Причина: `.git` уже весит 346 МБ из-за бинарных блобов. Файл там **не
  восстанавливается из репозитория** — при пересоздании сервера положить заново.
- **Всё, что рисует WebGL, оборачивается в `ClientOnly`.** Сборка гоняет приложение
  через `renderToString` в Node, где WebGL нет; `<Canvas>` в серверном дереве уронит
  или подвесит сборку.
- **Скрипт пререндера (`src/prerender.jsx`) не импортировать из клиентского кода.**
  Когда он лежал в общем entry, `renderToString` уезжал в браузерный бандл вместе
  с `modulepreload` на 444 КБ мёртвого веса.
- **Версии запинены точно, без `^`.** React строго `19.2.8`: это единственное окно,
  где сходятся требования R3F (`>=19 <19.3`) и остального. `three` — `0.185.1`,
  потому что `postprocessing@6.39.4` требует `< 0.186.0`.
- Бюджет — **400 КБ gzip** на то, что грузит браузер. Проверяется в CI, сборка падает
  при превышении.
